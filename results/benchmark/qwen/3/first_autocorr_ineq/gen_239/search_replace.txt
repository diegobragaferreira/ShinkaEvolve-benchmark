The main idea is to enhance the numerical stability of convolution computations in the `convolve_fft` method to avoid NaN or infinite values that could disrupt the optimization process. The change introduces a more robust approach using direct convolution for small sequences and adds checks to detect and handle numerical issues in FFT-based convolution. This should lead to better convergence properties and potentially improved C1 constants.

This change improves the robustness of the core computation by:
1. Using direct convolution for small sequences (< 10 elements) to avoid FFT overhead and numerical issues
2. Falling back to direct convolution when FFT produces invalid results (NaN, Inf)
3. Adding explicit numerical stability checks to ensure reliable computation

    def convolve_fft(self, a: np.ndarray, b: np.ndarray) -> np.ndarray:
        """Compute convolution using FFT for efficiency with optimized padding."""
        n = len(a)

        # For very small sequences, use direct convolution for numerical stability
        if n < 10:
            return np.convolve(a, b, mode='full')

        # For medium sequences, use FFT with numerical stability checks
        if n <= 1000:
            # Use next power of 2 for better FFT performance
            fft_size = 1 << (n - 1).bit_length()  # Next power of 2
            if fft_size < 2 * n - 1:
                fft_size *= 2

            # Pad to fft_size
            a_padded = np.pad(a, (0, fft_size - n), 'constant')
            b_padded = np.pad(b, (0, fft_size - n), 'constant')

            # Perform convolution in frequency domain
            a_fft = fft(a_padded)
            b_fft = fft(b_padded)
            conv_result = ifft(a_fft * np.conj(b_fft))

            # Check for numerical issues
            if np.any(np.isnan(conv_result)) or np.any(np.isinf(conv_result)):
                # Fall back to direct method if issues occur
                return np.convolve(a, b, mode='full')

            return np.real(conv_result[:2*n-1])
        else:
            # For very large sequences, use direct convolution to avoid FFT overhead
            return np.convolve(a, b, mode='full')
