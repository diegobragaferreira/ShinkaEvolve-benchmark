<DESCRIPTION>
The current implementation of convolution constraint generation in `solve_convolution_lp` constructs the full convolution matrix explicitly, which is computationally expensive and memory-intensive. This change replaces the explicit matrix construction with a more efficient approach by using FFT properties to compute constraints directly without forming large matrices. This will significantly improve performance, especially for longer sequences.

The key insight is that convolution constraints can be represented more efficiently by exploiting the structure of convolution as a Toeplitz matrix, but without constructing the entire matrix. Instead, we'll compute the constraints on-demand during optimization.
